El recorrido se puede ejecutar automáticamente en una finca temporal de QA o de forma manual en una finca de pruebas existente.

Pruebas automatizadas en Chrome

Ejecuta el script de QA desde la raíz del repositorio.

python3 scripts/run_qa_tests.py

Necesitas Python 3, JDK 17, Node.js 22.18 o posterior, Docker en ejecución y Google Chrome instalado. Instala las dependencias del frontend con npm ci desde frontend antes de la primera ejecución. En macOS el script busca el JDK 17 instalado si JAVA_HOME apunta a otra versión.

  1. El script inicia PostGIS en un contenedor temporal y usa esa base para las pruebas del backend.

  2. Ejecuta las pruebas unitarias y la compilación del frontend.

  3. Levanta una API local y abre Chrome para el recorrido de la finca. Registra una cuenta temporal, inicia sesión, crea la finca QA y recorre los flujos de campo, bloque, surco, riego, fertilización y cosecha. Una tarjeta indica cada paso y el recorrido avanza automáticamente.

  4. Ejecuta la suite de Playwright en ventanas visibles de Chrome para escritorio y móvil. Incluye el alta real de una cuenta y sus primeros registros agrícolas contra la API de QA.

Para leer con más calma cada paso, puedes aumentar la pausa. La pausa predeterminada es de un segundo.

python3 scripts/run_qa_tests.py --step-delay-ms 2000

El script usa postgis/postgis:16-3.7 por defecto. Puedes seleccionar otra imagen de PostGIS con --postgis-image. En la primera ejecución se pueden descargar la imagen y las dependencias de Gradle.

La API y PostgreSQL usan puertos locales separados de los servicios de desarrollo. El script detiene la API y elimina el contenedor y sus datos de QA al finalizar, incluso si falla una prueba. Los informes y las capturas quedan disponibles para revisar el resultado.

ResultadoUbicación
Pruebas de Gradlebuild/reports/tests/test/index.html

La terminal muestra el identificador de la ejecución y el resultado de cada etapa. El comando devuelve un código distinto de cero si alguna etapa falla. Para revisar los pasos y las capturas del recorrido, ejecuta desde frontend el comando siguiente con ese identificador.

npx playwright show-report "playwright-report/ID_DE_EJECUCION/walkthrough"

Correcciones verificadas

  • Campos en móvil. El botón Nuevo campo vuelve a estar disponible. La barra de acciones se ajusta a pantallas estrechas.

  • Mapas. La brújula deja libre el control de zoom y el panel lateral de escritorio queda debajo de la barra de capas. Las pruebas comprueban el zoom, la comparación de humedad y nutrientes en un solo mapa y la selección de bloques tras cerrar los paneles superpuestos.

  • Riego e inspecciones. Las pruebas usan las entradas actuales de Sectores e Infraestructura, verifican el volumen estimado y la duración efectiva en la tabla de ejecuciones, y comprueban que la revisión de una inspección cambia el estado que muestra el mapa sanitario.

  • Fotos y CSV. La prueba de fotos usa una respuesta simulada con el formato del informe de consumo de agua y comprueba la carga autenticada y la vista previa tras recargar. La prueba de exportación verifica la tabla de actividades y que el CSV descargado solo contiene la actividad filtrada.

Recorrido con inicio de sesión manual

La prueba manual-agricultural-workflow.spec.ts automatiza el recorrido de una finca existente después de que tú inicies sesión manualmente. Crea datos reales marcados como prueba, por lo que se debe usar contra una finca aislada de QA o una copia de la finca, nunca contra información operativa.

Qué verifica

  1. Inicio de sesión manual en una ventana de Chrome visible.

  2. Selección explícita de la finca indicada.

  3. Campo, lote/bloque y surco.

  4. Sector, medición, programación, tarea y ejecución de riego.

  5. Análisis, plan, aprobación, tarea, aplicación y seguimiento de fertilización.

  6. Ciclo de cultivo y registro estructurado de cosecha.

La aplicación actual no ofrece un plan de cosecha separado. El último paso comprueba el flujo que sí existe: ciclo de cultivo + registro de cosecha con rendimiento, calidad y merma.

Requisitos

  • API de Agro Core levantada en http://localhost:8080.

  • Frontend con dependencias instaladas: cd frontend && npm ci.

  • Chromium disponible para Playwright: npx playwright install chromium.

  • Una sesión ADMIN o SUPERVISOR de la finca. Este recorrido crea y aprueba planes de fertilización, cuyas acciones de gestión requieren uno de esos dos roles. AGRONOMIST puede configurar perfiles y revisar análisis, pero no puede crear ni aprobar esos planes por sí solo.

  • Al menos un cultivo creado en el catálogo de esa finca; se necesita para crear el bloque y el ciclo.

  • Una finca de pruebas. La prueba no borra sus registros para que puedas inspeccionar cada resultado.

Ejecución paso a paso

Desde la carpeta frontend, reemplaza el nombre de la finca por el nombre exacto que aparece en el selector de la aplicación:

AGRO_MANUAL_E2E=1 \
AGRO_E2E_ALLOW_WRITES=SI \
AGRO_E2E_FARM_NAME='Finca QA' \
PWDEBUG=1 \
npx playwright test tests/manual-agricultural-workflow.spec.ts --project=desktop --workers=1

Se abrirán Chrome y Playwright Inspector. Inicia sesión tú mismo; el script se queda detenido. Después pulsa Resume en el Inspector. Tras cada etapa el script vuelve a detenerse, deja una tarjeta verde en la esquina inferior derecha de la página y te permite revisar exactamente qué creó antes de continuar.

Para ejecutar el mismo recorrido visible sin detenerlo en cada etapa:

AGRO_MANUAL_E2E=1 \
AGRO_E2E_ALLOW_WRITES=SI \
AGRO_E2E_FARM_NAME='Finca QA' \
AGRO_E2E_PAUSE_EVERY_STEP=0 \
AGRO_E2E_STEP_DELAY_MS=1200 \
npx playwright test tests/manual-agricultural-workflow.spec.ts --project=desktop --workers=1 --headed

Seguridad y personalización

  • AGRO_E2E_ALLOW_WRITES=SI es obligatorio para evitar ejecuciones accidentales.

  • AGRO_E2E_FARM_NAME es obligatorio: la prueba no elige la primera finca por defecto.

  • Cada registro lleva E2E-MANUAL y una marca de fecha/hora. Puedes cambiar el prefijo con AGRO_E2E_PREFIX='QA-REGRESION'.

  • Por defecto las geometrías se crean alrededor de -74.1, 10.5. Para ubicarlas en un punto de prueba de tu mapa, define AGRO_E2E_LONGITUDE y AGRO_E2E_LATITUDE.

  • Al finalizar, Playwright guarda video, trace, capturas y una captura final en frontend/test-results/. Puedes abrir un trace con npx playwright show-trace test-results/<carpeta>/trace.zip.
